# 产品原则与当前设计决策

本文件是贡献评审的产品依据，与 [贡献指南](../CONTRIBUTING.md) 和 [界面与文案规范](UI_AND_COPY.md) 配合使用。

## 定位与优先级

**OJ Insight 是以跨 OJ 数据整合为基础、训练辅助为补充的应用。**

核心价值是让选手可靠地汇集、查看和理解自己的跨平台记录。优先维护数据源、同步可靠性、多账号、统计口径、Rating、难度、活动记录、展示和导出。辅助训练功能围绕这些记录和实际练习过程展开，不能因功能数量增长而挤占主线维护或增加日常使用负担。

“辅助”不表示现有训练功能可以随意删除。新功能的优先级与已有功能的维护责任应分开判断。

非主线扩展由维护者明确评估用户价值、与产品方向的联系、界面及配置成本、依赖和维护负担。不得以“功能更多”为默认目标。具体提案要求见 [贡献指南](../CONTRIBUTING.md#非主线功能如何评审)。

## 数据必须可信

- 区分首次 AC、当日去重 AC、AC 提交数和平台活动量；修改去重键、时区、统计范围时说明影响。
- 缺失、受限、加载失败和真实零值是不同状态。汇总记录不能被伪造成逐题提交。
- 各 OJ 的 Rating 和难度保留原体系；能力画像等派生指标应说明依据、样本不足和局限，不宣称是跨平台官方排名。
- 数据源失败时保留可用缓存并说明状态。强制刷新、清空、账号移除的语义不能混淆。
- 无法取得的 verdict 不能推断成 WA。赛时提交记录和个人 AC 统计各自保留清晰的用途。
- 新的数据源必须说明可取得范围、更新方式、失败回退与验证方法；README 不能把局部能力写成全量支持。

## 本地数据与用户控制

个人记录、账号和导出保存在本地，不要求注册 OJI 账号。社区分享是显式操作，不自动上传个人提交、笔记或代码。凭据不进入常规导出、日志和测试样例。

备份、导入、清空、迁移和更新需考虑数据完整性及中断恢复。增加云端保存、遥测、自动上传或新的常驻服务时，应单独提出方案，明确数据去向与用户控制方式。

## 正反馈是产品体验的一部分

OJI 保留问候、打卡反馈、适度鼓励和训练提示，帮助用户看到自己的积累。简洁不等于删除温度。

允许调整不自然、重复或说教的表达，但应保留原有用途、触发时机和反馈效果。删除整组语录、取消反馈、改变出现频率或替换为纯状态文字，都属于产品行为调整，需要单独说明并经维护者确认。

正反馈应轻量、自然，与场景相符。不夸大能力，不制造刷题焦虑，不把用户未完成训练描述成失败。数据真实性不会为了鼓励而让步。

## 当前已确认的决策

以下是当前约定，可以通过明确讨论修订；不要仅根据个人审美或一次“清理”任务重新定义。

| 范围 | 当前决定及原因 |
| --- | --- |
| 收藏夹 | 整理题目、题单、博客等链接；题单负责训练组织和完成进度，避免职责重叠 |
| 题单与比赛 | 题单是可复用集合，Contest 是配置快照，Match 是一次 VP，避免互相覆盖 |
| 个性化组题 | 从可靠目录和本地已做记录筛候选池，再交给大模型编排；不把已有题单当作初筛来源 |
| 提交与复盘 | 提交仍在原 OJ 完成，OJI 汇集可取得的数据和笔记辅助复盘 |
| 小助手 | 工具栏独立入口；结束归档手记，未完成保留草稿；Companion 接入用于准备草稿 |
| 平台导航 | “平台”浮窗包含“综合总览”和各 OJ；Trackers 及其内部名称保持现有命名 |
| 训练导航 | 题单内切换本地与推荐；模拟赛、参赛区、赛后分析由外部浮窗切换，避免重复入口 |
| QOJ 凭据 | 用户填写完整 `cookie_name=cookie_value`；不猜名称，不恢复应用内 QOJ 登录入口 |
| 国际化 | 保留现有内容，仍标为开发中，语言切换入口暂时隐藏 |
| 文档 | README 专注产品介绍，操作步骤由用户手册承担 |

## 决策如何更新

影响定位、统计口径或上述体验的 PR，应链接确认记录，并说明原决定、改变原因、影响和迁移或回退办法。合并时同步更新本文件；旧发布记录保留历史事实。

维护者的新明确决定可以修订现有约定。发现代码、文档和任务要求不一致时先指出，不自行把任一旧实现当作永久规则。
