# 界面与文案规范

先阅读 [产品原则](PRODUCT_PRINCIPLES.md)。界面调整应帮助用户查看数据和完成当前任务，并保留已经确认的反馈体验。

## 文案按用途处理

| 类型 | 目标 | 修改边界 |
| --- | --- | --- |
| 操作说明 | 说明用户此刻能做什么 | 删除重复解释，保留必要条件和下一步 |
| 状态与错误 | 说明发生什么以及能否继续 | 区分未配置、无记录、失败和受限，不用笼统错误替代原因 |
| 数据解释 | 防止误读统计结果 | 保留范围、口径、来源限制等必要信息，可调整展示层级 |
| 问候与正反馈 | 让训练过程有温度 | 可以润色，不擅自删除反馈内容、触发或效果 |
| 训练提示 | 提供与当前场景相关的帮助 | 精简说教和重复，取消整组提示需单独讨论 |

## “去 GPT 味”具体指什么

减少空泛夸赞、万能结论、重复解释、口号、过度修饰和替用户下判断。使用具体、自然、易懂的中文，不把所有句子改成冷硬的状态标签。

示例仅用于说明改写方向，并非当前界面的逐字引用：

| 修改前 | 可用方向 | 原因 |
| --- | --- | --- |
| 释放你的无限潜能，开启算法成长新篇章 | 记录训练，查看进步 | 去掉空泛宣传 |
| 请注意，你可以通过点击刷新按钮来刷新列表 | 刷新列表 | 删除重复步骤 |
| 欢迎回来，慢慢来就很好 | 保留，或做同等温度的润色 | 属于正反馈，不能因为“不提供操作信息”而删除 |
| 当前平台没有这一口径的逐日数据 | 保留必要含义 | 解释缺失数据，避免用户误认成零 |

当前需特别关注的反馈入口：

- `src/pages/DashboardPage.tsx` 中的 `greeting`、`CHECKIN_MESSAGES`、打卡反馈与效果。
- `src/lib/ui.ts` 的 `SYNC_TIPS`，以及 `src/hooks/useSync.ts` 的展示流程。

文案 PR 需要检查使用点，不能仅删除字符串或以构建通过作为验收。问候、同步提示和打卡完成是不同场景，不宜混成一条通用提示。

## 导航和操作位置

- 平台、Trackers、训练中心浮窗均有标题。平台 Logo 容器与图片尺寸应协调，图片完整显示。
- 点击侧栏分组直接展开；点击浮窗条目切换页面后保留浮窗，鼠标离开后关闭，保留键盘操作能力。
- 训练中心保留分组与快捷入口；题单内部切换本地和推荐，模拟赛等页面不重复提供同一组导航按钮。
- 设置默认打开数据源，数据源位于最左侧；同步全部置于页头右上角。
- 推荐题单刷新、投稿与审核，以及题单导入、新建等主要操作位于相应页头。窄窗口可有序换行，不挤压文字或遮住内容。
- 不以统一模板为由恢复某个 OJ 暂时没有数据支持的图表或重复平台切换。

## 字体、颜色与布局

- 英文标题和总览 OJ 名称使用项目随附的 Inter；中文使用既有回退字体。
- 字体、字重和颜色分别控制。统一字体不代表把白色标题改成绿色；绿色小标题使用已有主题规则。
- 避免父元素粗体与 `strong` 默认更粗的字重叠加；能力画像平台名称当前采用 600。
- 复用 `tokens.css` 的主题和平台变量，保留 OJ 各自的颜色与难度语义。
- 长题名应能读全或方便查看全文；不要以裁掉关键内容解决布局问题。
- 修改共用选择器时检查所有使用点，尤其是 Portal 浮窗、嵌入页面和独立小助手窗口。
- 确认亮色、灰色、暗色、大字号、最小窗口及侧栏折叠状态；重视点击区域、焦点、层级和溢出。

## 评审证据

给出代表性的修改前后文案或截图。单独列明新增、删除、隐藏或改变触发的内容；解释保留必要数据说明和正反馈的方式。涉及交互的变更验证实际流程，不能仅更新测试以适应被误删的功能。
